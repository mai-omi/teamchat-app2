# チームチャットアプリ

20人ほどのソフトウェア開発会社向けの、社内チャットアプリです。

## 何のアプリか

社内の連絡が個人あてのチャットとメールに散らばっていて、過去のやり取りを探し回ることになっていた、という課題から作られました。**話題ごとに分かれたチャンネルで会話ができて、あとから検索で探せる**ことを目的にしています。

利用者は3種類です。

| 利用者 | できること |
| :-- | :-- |
| 社員 | アカウントを作ってログインし、チャンネルで会話する |
| チャンネルを作った人 | そのチャンネルについてだけ、できることが増える（編集・削除・メンバー管理） |
| ログインしていない人 | 公開APIから、公開チャンネルの内容を読むだけ |

今回のスコープでは、新着メッセージの自動表示・通知・ダイレクトメッセージ・ファイル添付・リアクション・既読管理・管理者機能は作っていません（理由は `docs/spec.md` 4.参照）。

## できること

機能一覧の詳細・根拠は `docs/design/features.md`（F-01〜F-31）を参照してください。

- **アカウント**：新規登録、ログイン、ログアウト
- **チャンネル**：作成（名前・説明・公開/プライベート）、編集・削除（作成者のみ）、一覧表示。公開範囲は作成後に変更できません
- **メンバー管理**：プライベートチャンネルへのメンバー追加・削除（作成者のみ。作成者自身は外せません）。公開チャンネルにはメンバー管理の操作がありません
- **メッセージ**：投稿、自分のメッセージの編集（編集済みの印が付きます）・削除（削除後も「このメッセージは削除されました」が場所に残ります）
- **スレッド**：メッセージへの返信（1段のみ）。元メッセージに返信件数を表示
- **検索**：キーワードによるメッセージ検索。結果は自分が見られるチャンネルのものだけに絞られます
- **公開API**：ログイン不要の読み取り専用API（下記「公開API」参照）

## 動かす

> ⚠️ 先に、80番ポートと3306番ポートを使っている別のアプリ（他の `laravel-practice` 配下のプロジェクトなど）を止めてください。動かしたままだと `sail up -d` で `Bind for 0.0.0.0:80 failed: port is already allocated` になります。そのフォルダで `./vendor/bin/sail stop` を実行してから始めてください。

```bash
git clone <このリポジトリのURL> teamchat-app2
cd teamchat-app2
```

```bash
# 1. ライブラリを取ってくる
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    -e COMPOSER_CACHE_DIR=/tmp/composer_cache \
    laravelsail/php82-composer:latest \
    composer install

# 2. 環境変数のファイルを作る
cp .env.example .env

# 3. コンテナを起動する
./vendor/bin/sail up -d
```

コンテナが `Up` になっても、データベースはまだ中で立ち上がっている途中です。`./vendor/bin/sail ps` の `mysql` の欄が `Up (healthy)` になるまで待ってください（手元では30秒ほど）。

```bash
# 4. アプリケーションキーを作る
./vendor/bin/sail artisan key:generate

# 5. テーブルを作り、初期データを入れる
./vendor/bin/sail artisan migrate --seed
```

ブラウザで <http://localhost> を開いてください。

## ひととおり触ってみる

初期データには、公開チャンネル3つ（全体連絡・開発・雑談）とプライベートチャンネル1つ（採用プロジェクト、メンバーは佐藤 太郎・鈴木 花子）が入っています。

1. **チャンネル一覧**を開き、公開チャンネルとプライベートチャンネルの見え方の違いを確認する（メンバーでないプライベートチャンネルは一覧にも出ません）
2. 公開チャンネルを開いて、**メッセージを投稿**する。自分のメッセージだけに編集・削除の操作が出ることを確認する
3. 返信が付いているメッセージの「**返信n件**」を開き、右側のスレッドパネルで返信する
4. 自分のメッセージを**編集**して「編集済み」の印が付くこと、**削除**して「このメッセージは削除されました」が残ることを確認する
5. トップバーの検索から、メッセージ本文に含まれるキーワードで**検索**する
6. 「チャンネルを作る」から新しいチャンネルを作り、プライベートにした場合は**メンバー管理**画面でメンバーを追加・削除する
7. 作成者としてチャンネルを**編集・削除**する（削除はチャンネル名の入力による確認があります）

対応する画面の一覧は `docs/design/screens.md`（SC-01〜SC-09）、見た目の正は `mockup/index.html` です。

## 公開API

ログイン不要の読み取り専用APIです。書き込み系のAPIはありません。詳しい設計・レスポンス例は `docs/design/permissions-api.md` 3.を参照してください。

| メソッド | パス | 内容 |
| :-- | :-- | :-- |
| GET | `/api/channels` | 公開チャンネルの一覧（名前・説明）を返す |
| GET | `/api/channels/{channel}/messages` | 指定した公開チャンネルのメッセージ一覧を返す（削除済みは含めない） |

```bash
curl http://localhost/api/channels
```

プライベートチャンネルの情報は、名前も含めて一切返しません。存在しないチャンネルIDと、プライベートチャンネルのIDを指定した場合は、どちらも同じ404になります。
